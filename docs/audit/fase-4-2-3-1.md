# Chiusura del divario v2 — Gruppo 1: metadati e selezione

> **Data**: 2026-10-26
> **Stato**: gruppo 1 chiuso. Gruppi 2-5 non iniziati.

---

## Cosa è cambiato

Cinque funzioni del bridge non leggono più il documento legacy tramite
`with_active_document`: passano dai metodi semantici del backend.

| Funzione | Prima | Ora |
|---|---|---|
| `get_layers_metadata` | costruiva i DTO leggendo `doc.layers` | `backend.layers_metadata()` → DTO |
| `set_selection` | `doc.set_selection(...)` | `backend.set_selection(...)` |
| `clear_selection` | `doc.clear_selection()` | `backend.clear_selection()` |
| `has_active_selection` | `doc.has_active_selection()` | `backend.has_selection()` |
| `get_selection` | serializzava `pizzico_core::RectSelection` | serializza `SelectionMeta` |

### Il dettaglio che conta: la forma JSON

La UI legge `{ x, y, width, height, active }`. Quel contratto non può cambiare, quindi
il trait espone `selection_meta() -> SelectionMeta`, una struct con **esattamente** quei
campi e gli stessi nomi. Il backend legacy la costruisce da `pizzico_core::RectSelection`;
il backend v2 dal proprio stato. La serializzazione resta identica perché i nomi dei
campi e l'ordine coincidono.

Se avessi inventato un tipo diverso, il `.d.ts` sarebbe rimasto uguale ma la UI avrebbe
smesso di funzionare a runtime — i due gate non coincidono, ed è per questo che esiste
questo test.
